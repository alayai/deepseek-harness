# Agent Note: Host 拥有的 dsh-server 云端执行目标

Status: implemented

[English](2026-11-17-dsh-server-cloud-target.md) | 中文

## 问题

DSH 用户需要云端工作空间与隔离的远程资源，并且在登录前保留现有本地流程。仅转发部分工具，会使本地 API、上传与已经运行的任务仍能在客户端机器执行。网络故障绝不能静默地把云端工作转移到本地 DSH。

## 决策

[Cloud server 包](../../../../packages/cloud/server/README.zh.md)为每个 Host 管理一个执行目标。登录同步保留该目标、关闭本地准入，并等待已注册的本地工作结清后才开始 PKCE。访问令牌留在 Host 内存。由应用选择的生成式 Remote 仅向 Host 所有者提供展示状态与有大小限制的服务端请求。

API Gateway 提供通用、由 fiber 拥有的 `guard` 与 `drain` 操作。云端所有者将其与连接 HTTP 准入、工具守卫、Agent 步骤前钩子共同应用。流清理与单次调用异步任务必须结清；超时会让云端准入保持暂停。代次变化会拒绝旧响应。退出串行撤销授权，失败时继续阻止本地执行。

客户端通过 `shell.overlay` 挂载云端资源视图，调用服务端拥有的租户、工作空间、沙箱、会话、文件、对象与桌面 API。它不改变 Agent loop 语义，也不把服务端事件解释为本地 Session 记录。

## 考虑过的替代方案

**把服务压缩包安装为 Desktop 插件。** 服务包不提供原生 Client 组合，安装它也不能路由所有现有资源路径。因此 DSH 集成放在有类型的 Host/Client 包中。

**云端使用期间继续开放本地工具。** 这会允许远程故障后意外执行本地操作。因此所选执行目标会持续阻止本地业务入口，直到显式退出。

**首先重写现有会话控制器。** 云端操作具有服务端拥有的身份与持久操作结果。独立视图保留这些语义，使集成无需改变已发布的本地 Session 行为。

## 结果与影响

用户获得明确的云端执行目标与失败时保持关闭的恢复行为。撤销授权失败时，可能需要等服务端恢复可达后才能返回本地。执行目标属于整个 Host，而非单个窗口。原生会话气泡、交互式 noVNC、分页与持久登录尚未包含在当前视图中。包内应用守卫不约束任意受信任插件对操作系统的直接访问。

## 验证

针对性测试覆盖目标保留、旧响应、授权撤销、并发退出、流准入与清理顺序。内置配置的 Client 组合测试使用默认本地状态 mock 执行本包。真实 Web PKCE 测试使用独立 Host 配置与开发环境 dsh-server；Windows 安装版 Desktop 验收仍是独立检查。
