# Agent Note: 让 Desktop 插件事务独立于主窗口导航完成

Status: implemented

[English](2026-09-24-desktop-plugin-install-completion.md) | 中文

## 问题

Desktop 插件管理器通过 Electron IPC 调用包变更。变更会写入 profile 并重启 Host，但主应用窗口加载应用文档可能更慢。如果在 IPC 返回前等待这个无关的导航，插件包虽然已经安装，插件管理器仍会一直显示安装中。

## 决策

插件变更处理器在 profile 变更和后端重启完成后返回。它启动主窗口的应用导航，但不再把该导航纳入插件管理器 IPC 的完成条件。导航失败仍通过现有启动错误路径报告，同时插件管理器可以立即刷新已安装清单并显示操作完成。

## 考虑过的替代方案

**继续把导航放在变更 Promise 中。** 这种方式保持严格顺序，但会把包操作反馈绑定到无关的渲染文档；当文档加载缓慢或被阻塞时，即使安装已完成，界面也可能长期保持忙碌状态。

**pnpm 退出后立即报告成功。** 这样会在重启 Host 就绪之前把包显示为已安装，界面可能在激活仍未完成时显示成功。处理器仍会等待后端重启。

**在 IPC 等待期间由渲染器轮询 profile。** 轮询会让 UI 重复事务所有权，并可能在 pnpm 或 Host 重启仍持有 profile 锁时提前释放控件。完成状态继续由 IPC 负责。

## 后果

插件管理器反馈反映已完成的 profile 事务和 Host 重启，而不是主窗口加载时间。主窗口可以独立完成加载；失败仍进入现有启动错误处理。测试必须保持 IPC 完成路径独立于应用文档导航。

## 测试

Desktop 主进程回归 harness 会在插件变更后阻塞主应用导航，并断言替换 Host 就绪后插件 IPC Promise 仍然返回。完整测试依赖未安装的环境中，`git diff --check` 和 JavaScript 语法检查覆盖已编辑源码。
